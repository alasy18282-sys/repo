# APK / IPA Studio

## Работа в окне

Запустите E:\apk\APK_Studio.ps1. Вверху появился выбор **APK / IPA**.
Настройки двух платформ сохраняются раздельными полями одного файла:
E:\apk\config\apkstudio.json. Переключение не удаляет введённые значения.

### IPA

- **Разобрать IPA**: проверка ZIP и структуры Payload, XML/binary Info.plist,
  Bundle ID, название, версии, минимальная iOS, архитектуры Mach-O (thin/fat),
  команды шифрования и подписи, вложенные фреймворки, наличие Firebase.
  JSON-отчёт сохраняется в E:\apk\test_out\ipa-analysis.
- **Извлечь IPA**: распаковка в новую подпапку выбранной директории.
  Архивные пути проверяются до записи; существующие файлы не перезаписываются.
- **Собрать IPA (без подписи)**: отдельный выходной IPA с изменениями
  Bundle ID, отображаемого названия, версии и номера сборки.
  Пустые поля сохраняют исходные значения. Существующий выходной файл
  не перезаписывается: для следующей сборки задайте новое имя.
- **iOS Firebase**: необязательный GoogleService-Info.plist для выбранного Bundle ID.
  Обновляются найденные копии этого файла и схема Google Sign-In.
  Android google-services.json сюда не подходит.
- **Двоичные патчи**: необязательный JSON-план точных замен одинаковой длины.
  Каждая замена требует относительного ZIP-пути и точного количества совпадений.
  Проверяются длина, совпадения и корректность Mach-O после перепаковки.

Все выходные записи повторно читаются с проверкой CRC и SHA256. Хеш исходного
архива проверяется повторно. Рядом с результатом сохраняется .ipa.report.json
с изменениями, хешами записей и явно неподписанным статусом.

Пример схемы плана (не готовый патч для игры):

    {
      "patches": [
        {
          "path": "Payload/Example.app/example.dat",
          "find_hex": "41424344",
          "replace_hex": "45464748",
          "expected_matches": 1
        }
      ]
    }

## Подпись и ограничения

По вашему выбору сертификат не используется. Итог имеет статус
unsigned_requires_resigning, а не «готово к установке».
Старые подписи Mach-O могут оставаться в бинарных файлах, но после изменений
они недействительны. Перед обычной установкой требуется полноценная новая подпись,
подходящий профиль и проверка на устройстве. В этой версии нет запуска подписанта
или автоматической установки на iPhone.

Дешифрование Mach-O, преобразование APK в IPA, компиляция iOS-кода и автоматический
перенос smali/OBB/Android keystore в iOS отсутствуют.
Зашифрованный Mach-O допускается к анализу, но блокирует перепаковку.
Смена основного Bundle ID при наличии .appex требует отдельной поддержки
идентификаторов расширений. Symlink-архивы отклоняются при проверке путей.
Это реализованный и проверенный набор операций для указанного IPA, а не обещание
поддержки любой IPA или работоспособности изменённой игры.

Документация Apple:
- [Provisioning profiles](https://developer.apple.com/documentation/technotes/tn3125-inside-code-signing-provisioning-profiles)
- [Подпись вложенного кода](https://developer.apple.com/documentation/Xcode/using-the-latest-code-signature-format)

## Зависимости и откат

Обработка IPA использует Python 3.10+ и стандартную библиотеку; Java/aapt не нужны.
Путь к интерпретатору хранится в E:\apk\config\python-path.txt.
APK использует прежние Java, aapt, apktool и Android-шаблоны.

Откат интерфейса и конфигурации: E:\apk\test_out\ipa-support\Rollback.ps1.
Исходные APK/IPA не изменяются. Добавленные инструменты и отчёты при откате
остаются на диске. Конфигурационные JSON содержат сохранённые пароли Android —
не публикуйте их.


## Замена IP в IPA

Добавлены поля IP сервера IPA и Исходные IP/домены (список через ;).
Для указанного IPA 0.17.0 выбран профиль адресов API:
46.101.200.35 и fra02.bolt.bolt-api.com → 84.21.173.237.
В будущих сборках IP редактируется прямо в форме; пустое поле отключает замену.
Каждый исходный адрес должен присутствовать отдельной строкой IL2CPP,
иначе сборка останавливается с конкретной ошибкой вместо молчаливого пропуска.

Замена обновляет длину и индекс строк IL2CPP. Пул строк переносится в конец
metadata-файла; остальные таблицы и все невыбранные строки остаются прежними.
Это поддерживает IP различной длины без повреждения соседних строк.
В отчёте указаны индексы строк и старые/новые смещения. Старые байты могут
оставаться в неиспользуемом пуле; проверяются реальные ссылки таблицы строк.

Новый результат: E:\\apk\\test_out\\ProjectRework-0.17.0-IP-84.21.173.237.unsigned.ipa

В этом результате заменены именно два адреса API. Прочие региональные,
matchmaking- и Photon-адреса не затрагивались. Для их явной замены можно
добавить нужные точные исходные строки в поле Исходные IP/домены.
Замена строк подтверждена статически, а установление сетевого соединения,
TLS, совместимость протокола сервера и запуск на iPhone не проверены.
Предыдущий файл без IP-замены также сохранён.
